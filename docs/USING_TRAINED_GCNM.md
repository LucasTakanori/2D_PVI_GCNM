# Using a trained PVI-GCNM

This guide covers inference with the production two-stage coordinate GCNM,
including checkpoints trained with projected-fine nonlinear physics. It assumes
that you already have the two trained checkpoint files.

## 1. What you need

Inference requires four matching pieces:

1. the two stage checkpoints;
2. the YAML configuration for the measured ring;
3. that ring's forward mesh, inverse mesh, and image/coarse-to-fine mapping;
4. the external Python PVI solver.

The ring configuration and mesh files are versioned in this repository. Model
weights are not committed. A checkpoint is tied to its configuration and mesh
files by SHA-256 hashes, so a model trained for one ring must not be used with a
different ring.

Use the validated source version:

```bash
git clone https://github.com/LucasTakanori/2D_PVI_GCNM.git
cd 2D_PVI_GCNM
git checkout validated-batch50-20260909

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .

export PVI_SOLVER_ROOT=/absolute/path/to/Peripheral-Vascular-Impedance-Imaging/python_port/pvi_solver
export PYTHONPATH="$PWD:$PVI_SOLVER_ROOT:${PYTHONPATH:-}"
```

## 2. Arrange the checkpoint files

The two files must have the same base name followed by `_0.pt` and `_1.pt`:

```text
weights/
└── US120/
    ├── coordinate_direct_projected_fine_0.pt
    └── coordinate_direct_projected_fine_1.pt
```

For this example:

```python
checkpoint_dir = "weights/US120"
model_name = "coordinate_direct_projected_fine"
```

These must be complete training checkpoints, not bare PyTorch `state_dict`
files. The runtime reads the architecture, normalization scale, feature order,
and physics contract from each checkpoint. At minimum, the saved dictionaries
must contain the `state_dict`, `channels`, `in_channels`, `scale`,
`output_mode`, `use_coordinates`, and `physics_contract` fields produced by the
training code.

Only load checkpoint files you trust. PyTorch loads these complete checkpoint
dictionaries with `weights_only=False`. The `_0.pt` and `_1.pt` filenames
determine stage order, so do not rename or interchange them.

## 3. Prepare the voltage input

`CoordinateReconstructor` accepts a floating-point array with shape
`(frames, 32)`. The 32 columns are the differential EIT voltage measurements
from the configured eight-electrode stimulation/measurement protocol. They are
not the six BP-model channels.

The input must use the same sign, units, channel order, filtering, and temporal
reference convention as the data used to train the checkpoint. Do not pass raw
absolute voltage measurements to a checkpoint whose contract says
`measurement_contract=differential`.

For a synthetic NPZ generated by this repository:

```python
import numpy as np

with np.load("test.npz", allow_pickle=False) as source:
    voltage_50x32 = np.asarray(source["V"][:50], dtype=np.float64)
```

For production PVI files in which differential resistance is stored as
`(32, frames)`, use the shared sign convention instead of hardcoding a sign:

```python
import h5py
import numpy as np

from gcnm_pvi.hp_lp_signals import resistance_to_voltage

with h5py.File("participant.h5", "r") as source:
    resistance_hp = np.asarray(
        source["data/pviHP/resistance"][:, :50], dtype=np.float64
    )
    resistance_lp = np.asarray(
        source["data/pviLP/resistance"][:, :50], dtype=np.float64
    )

voltage_50x32 = resistance_to_voltage(resistance_hp + resistance_lp).T
assert voltage_50x32.shape == (50, 32)
```

`resistance_to_voltage` applies `delta_V = -I * delta_R` with the production
current `I=-0.01 A`. If a different current or preprocessing pipeline was used,
make that conversion before inference and verify it against the checkpoint's
training contract. The example combines HP and LP for the full differential
model. If a checkpoint was deliberately trained on only one temporal
component, supply that same component instead.

Some older exported real-data NPZ packs stored a display-oriented voltage sign
and their evaluation scripts flipped it before the physics calculation. Do not
copy that flip onto synthetic `V` arrays or onto the raw-resistance conversion
above. Check the provenance of an older NPZ before using it directly.

## 4. Reconstruct one 50-frame beat/buffer

Create the reconstructor once and keep it alive. Construction loads both GCNs,
the meshes, mappings, baseline physics, and private worker lanes.

```python
from pathlib import Path

import numpy as np

from gcnm_pvi.representations import CoordinateReconstructor

config = Path("configs/rings_b045/US120.yaml")
checkpoint_dir = Path("weights/US120")
model_name = "coordinate_direct_projected_fine"

with CoordinateReconstructor(
    config=config,
    checkpoint_dir=checkpoint_dir,
    model_name=model_name,
    device="cuda:0",
    physics_workers=16,
    forward_backend="sparse",
) as reconstructor:
    stage_1, stage_2, diagnostics = reconstructor.reconstruct_batch(
        voltage_50x32,
        model_batch_size=50,
        physics_workers=16,
        compute_stage2_residuals=False,
    )

    # stage_2 is the final reported GCNM reconstruction.
    stage_2_images = np.stack(
        [reconstructor.mappings.elem_to_image_grid(frame) for frame in stage_2]
    )

np.savez_compressed(
    "gcnm_reconstruction.npz",
    voltage=voltage_50x32,
    stage_1_elements=stage_1,
    stage_2_elements=stage_2,
    stage_2_images=stage_2_images,
)
```

For the US120 mesh, the returned shapes are:

```text
stage_1:        (50, 1330)   differential conductivity in S/m
stage_2:        (50, 1330)   final differential conductivity in S/m
stage_2_images: (50, 40, 40) rasterized final reconstruction
```

The number of mesh elements is ring-specific; obtain it from
`reconstructor.mappings.num_elements` rather than hardcoding 1330.

The checkpoint's `physics_mesh_mode` is selected automatically. A proper
projected-fine checkpoint therefore uses `F_f(P sigma_c)` and `J_f P` without
the caller supplying a mode. In the Python API, omit this argument or pass
`physics_mesh_mode=None`; the literal string `"auto"` is only accepted by the
benchmark command. Do not enable `allow_config_hash_mismatch` or
`allow_physics_mode_mismatch` during normal inference. A hash or mode error
usually means the wrong checkpoint, configuration, or mesh was selected.

## 5. Single-frame inference

The same method accepts any nonempty batch size. Run this call inside the
active `with CoordinateReconstructor(...)` block and preserve the leading frame
dimension for one frame:

```python
one_frame = voltage_50x32[0:1]  # shape (1, 32), not (32,)
stage_1, stage_2, diagnostics = reconstructor.reconstruct_batch(
    one_frame,
    model_batch_size=1,
    physics_workers=1,
    compute_stage2_residuals=False,
)
```

On the validated H100/16-CPU setup, repeated one-frame calls took about
22.71 ms/frame (44.03 frames/s), while 50-frame calls took 0.384 s per batch,
equivalent to 7.68 ms/frame (130.18 frames/s). Use 50-frame buffering for a
50 Hz stream.

## 6. Continuous 50 Hz operation

Keep the reconstructor resident for the entire recording session. The
acquisition process should accumulate 50 ordered samples while a reconstruction
worker processes the preceding buffer. Do not reconstruct the runtime for each
buffer. The following is the reconstruction consumer; its acquisition function
must read a completed buffer that the acquisition process filled independently.

```python
with CoordinateReconstructor(
    config,
    checkpoint_dir,
    model_name,
    device="cuda:0",
    physics_workers=16,
    forward_backend="sparse",
) as reconstructor:
    while acquisition_is_running:
        voltage_50x32 = acquire_next_50_differential_voltage_frames()
        _, final_elements, _ = reconstructor.reconstruct_batch(
            voltage_50x32,
            model_batch_size=50,
            physics_workers=16,
            compute_stage2_residuals=False,
        )
        publish_reconstruction(final_elements)
```

The acquisition/publish functions are application-specific placeholders. A
one-second buffer gives about 1.38 s first-frame-to-result latency on the
validated machine: 1.0 s to acquire the buffer plus about 0.38 s to reconstruct
it. Because reconstruction is faster than acquisition, the pipeline sustains
one complete 50-frame output every second after startup.

## 7. Residual diagnostics

Inside an active reconstructor context, `stage_1_forward_voltage_rms` is
produced while computing the required
second-stage physics. `stage_2_forward_voltage_rms` requires an additional
forward solution and is optional:

```python
stage_1, stage_2, diagnostics = reconstructor.reconstruct_batch(
    voltage_50x32,
    compute_stage2_residuals=True,
    stage2_residual_stride=10,
)

print(diagnostics["stage_2_forward_voltage_rms_indices"])
print(diagnostics["timings_seconds"])
```

Disabling the final residual does not change stage 1 or stage 2. It only skips
the extra post-reconstruction diagnostic calculation.

## 8. Validate a new checkpoint pair

Run the supplied benchmark before deployment. On Slurm:

```bash
mkdir -p logs

CONFIG="$PWD/configs/rings_b045/US120.yaml" \
CHECKPOINT_DIR="$PWD/weights/US120" \
MODEL_NAME="coordinate_direct_projected_fine" \
INPUT_NPZ="/path/to/held_out_test.npz" \
FORWARD_BACKEND="sparse" \
WARMUPS=2 \
REPEATS=10 \
sbatch slurm/launch_benchmark_gcnm_batch50.sh
```

The benchmark verifies checkpoint/config/mesh hashes, records the exact code
commit and selected input hash, compares one-frame and 50-frame outputs, and
reports initialization, component timing, throughput, p95/max latency, and
memory. Its parity gates are `1e-7 S/m` maximum absolute difference and `1e-6`
relative L2 difference.

For an explicit sparse-versus-dense output comparison, additionally set:

```bash
CROSS_BACKEND_REFERENCE=dense
```

## 9. CPU use

CPU-only execution is supported:

```python
with CoordinateReconstructor(
    config,
    checkpoint_dir,
    model_name,
    device="cpu",
    physics_workers=8,
    forward_backend="sparse",
) as reconstructor:
    stage_1, stage_2, diagnostics = reconstructor.reconstruct_batch(
        voltage,
        model_batch_size=50,
        physics_workers=8,
        compute_stage2_residuals=False,
    )
```

Do not assume the H100 timing applies to another CPU/GPU. Run the benchmark on
the deployment machine and keep `physics_workers` within its allocated CPU
count.

## 10. Common errors

- **`..._0.pt` or `..._1.pt` not found:** `checkpoint_dir` or `model_name` does
  not match the required two-file naming convention.
- **Configuration or mesh SHA-256 mismatch:** the weights were trained with a
  different YAML or mesh bundle. Select the matching ring files; do not bypass
  the check for production inference.
- **Stage checkpoints disagree on `physics_mesh_mode`:** stage 0 and stage 1 do
  not belong to the same trained model.
- **Voltage shape error:** supply `(frames, 32)`, including `(1, 32)` for one
  frame.
- **Non-finite voltage error:** remove or repair NaN/Inf values before
  reconstruction using the same policy used during training.
- **CUDA unavailable or out of memory:** use a valid CUDA device, reduce
  `model_batch_size`, or use CPU. Reducing `model_batch_size` changes execution
  memory and speed, not the trained model.
- **Worker request exceeds the resident pool:** choose the maximum worker count
  when constructing the reconstructor, then request no more than that count in
  `reconstruct_batch`.
- **Worker pool is closed:** do not reuse a reconstructor after leaving its
  `with` block; create a new context for another session.

The sparse backend changes only matrix storage and factorization. It preserves
the model architecture, weights, meshes, float64 FEM equations, per-frame
nonlinear forward solution, per-frame Jacobian, regularized update, and both
GCN stages. Existing trained models do not need to be retrained.
